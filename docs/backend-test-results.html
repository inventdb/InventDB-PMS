What the 11 known defects are

They are not broken tests. Each asserts the behaviour the code should have, for a bug found while writing the suite — recorded as a known defect rather than deleted or quietly asserted as correct.

  • 4 × a non-numeric limit or offset returns 500 with the raw Python error text, where a malformed query string should be a 400.
  • 3 × record ids reach the upstream URL without validation, so ? appends query parameters to the internal InventDB call and # truncates the path.
  • 3 × the raw-SQL guard only inspects the leading keyword, so SELECT 1; DROP TABLE … passes and is forwarded verbatim.
  • 1 × a JSON array error body from InventDB raises inside the parser and surfaces as a 500, hiding the real upstream status.

xfail_strict is enabled, so fixing any of them turns that test into a hard failure — which is the prompt to delete the marker. A fixed bug cannot silently regress, and cannot stay flagged as broken forever.

How to reproduce: cd backend && python -m pytest. Nothing in the suite opens a socket or needs a running InventDB instance.
